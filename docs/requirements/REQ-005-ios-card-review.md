# REQ-005 iOS 卡片流与每日回顾

## 1. 核心判断

值得做，而且只做消费侧。用户要的是在手机上用 flomo 的方式重温已有 Obsidian 笔记：打开就是卡片，按自己定的规则每天抽一批旧笔记回来看。这不是间隔重复，没有「记住了 / 忘了」，也不是把 Obsidian 搬到手机上。

本需求固定三个边界：

1. **零写路径不变**。本需求不新增任何写 Vault 的能力。回顾规则、当日批次只存在 App 沙箱，是与 `index.sqlite` 同类的派生物，删除后可重建，笔记本身不受影响。手机上新建、编辑、删除卡片不在本需求内，那会突破 [REQ-004](REQ-004-ios-read-only-client.md) 与 [ADR-010](../adr/ADR-010-ios-platform-strategy.md) 的只读边界。
2. **一张卡片等于一篇笔记**。不从正文切分问答，不发明新的卡片格式。卡片是 `IndexedNoteSummary` 的展示投影。
3. **只改 iOS 紧凑宽度**。iPad 常规宽度继续复用 REQ-001 的三栏，Mac 端零变化。

参考对象是 flomo 的卡片流与每日回顾（内容范围、时间范围、每日数量、同一天批次稳定），不复制其品牌、图标、文案或像素级布局。

## 2. 目标

- 在 iPhone 上打开 App 后，首页直接是按修改时间倒序的卡片流，不经过五入口导航；
- 用户用三项规则（内容范围、时间范围、每日数量）决定每天回顾哪些笔记；
- 同一个自然日多次打开回顾，看到同一批卡片；过零点后重新抽取；
- 标签过滤与搜索的结果集合与 Mac 端一致；
- 全流程不修改 Vault 中任何字节，Mac 端行为与测试零变化。

## 3. 术语与信息结构

| 术语 | 定义 | 归属 |
|---|---|---|
| 卡片 | 一篇笔记的展示投影：标题、摘要、最多 3 个标签、相对日期 | 值对象，不落库 |
| 卡片流 | 卡片的纵向列表，默认按修改时间倒序 | iOS 紧凑宽度首页 |
| 回顾规则 | 内容范围 + 时间范围 + 每日数量 | 值对象，按 Vault 存在沙箱 |
| 当日批次 | 某自然日按某规则抽出的有序卡片路径列表 | 实体，按 Vault 存在沙箱 |
| 内容范围 | 全部 / 含指定标签 / 排除指定标签 / 无标签 | 规则字段 |
| 时间范围 | 全部 / 一年 / 半年 / 三个月 / 一个月，按修改时间 | 规则字段 |
| 每日数量 | 4 到 24，步长 4，默认 8 | 规则字段 |

> [!important] 平台不变量
> 本需求不出现编辑入口。阅读面仍以 `editorSource == nil` 构造。iOS 的只读属性继续由文件成员与编译期条件保证，不改为运行时开关。

## 4. 功能需求

### FR-001 卡片流

1. iPhone（紧凑宽度）顶级入口改为三个：笔记、回顾、标签。「最近」与「收藏」从紧凑宽度顶级入口移除；最近由卡片流的时间倒序覆盖。
2. 「笔记」入口是卡片流：搜索框、标签过滤条、卡片列表，按修改时间倒序。
3. 一张卡片展示标题（无标题时用文件名）、正文摘要前 140 个字符（超出截断并加省略号）、最多 3 个标签（其余折为「+N」）、修改时间的相对日期。
4. 点卡片推入现有阅读面；返回后保留滚动位置与过滤状态。阅读面的 Wiki Link 跳转行为与 REQ-004 §4.4 一致。
5. 解析状态为失败的笔记仍占一个卡片位置，摘要处显示固定文案「这条笔记暂时无法读取」，其余卡片不受影响。

### FR-002 每日回顾

1. 「回顾」入口独立一页。未设置规则时进入规则设置；已设置时展示当日批次，顶部一行规则摘要与「调整规则」。
2. 规则三项：内容范围（全部 / 含指定标签 / 排除指定标签 / 无标签）、时间范围（全部 / 一年内 / 半年内 / 三个月内 / 一个月内）、数量（4、8、12、16、20、24，默认 8）。
3. 打开回顾时：若已有批次且日期为今天且规则未变，直接返回该批次；否则按规则从索引取候选，抽出指定数量，落盘后返回。
4. 抽取使用固定种子（本地日历日 + Vault 标识），同一天同一规则同一候选集的结果可复现。
5. 候选不足数量时全部给出，并在列表底部显示「符合规则的只有 N 条」。候选为空时显示「没有符合规则的笔记」与「调整规则」。
6. 修改规则并确认后，当日批次作废，下次进入按新规则重抽。确认文案为「按新规则重新抽取今日回顾？」，取消则保持原规则。
7. 批次写入沙箱失败时，当日仍展示抽到的结果，规则摘要处显示「本次回顾未能保存」，不弹错误打断。

### FR-003 标签过滤

1. 点卡片上的标签，卡片流只保留带该标签的笔记。
2. 匹配规则与 Mac 一致：完整标签身份精确匹配，选择 `project` 不包含仅标记 `project/mobile` 的笔记。
3. 过滤可清除，清除后回到全部。
4. 「标签」入口保留标签列表；点标签后推入的是预置了该过滤条件的卡片流，而不是笔记列表。

### FR-004 搜索

1. 卡片流顶部搜索框复用现有离线全文搜索。
2. 空查询回到时间倒序卡片流。
3. 搜索结果仍以卡片呈现。
4. 断网时可搜索已索引内容。

### FR-005 本机状态

1. 回顾规则与当日批次按 Vault 隔离，存在 App 沙箱，不写入 Vault，不写入 `index.sqlite`，不改变索引 schema。
2. 删除该状态后，笔记仍可浏览，回顾在下次打开时重新抽取。
3. 切换 Vault 不复用上一本 Vault 的规则与批次。

## 5. 交互映射

| 用户操作 | 紧凑宽度（iPhone）结果 | 常规宽度（iPad）结果 |
|---|---|---|
| 打开 App（已有 Vault） | 进入「笔记」卡片流 | 不变，仍为 REQ-001 三栏 |
| 点一张卡片 | 推入阅读面 | 不适用 |
| 从阅读面返回 | 回到原卡片流，滚动位置与过滤保留 | 不适用 |
| 点卡片上的标签 | 卡片流按该标签过滤 | 不适用 |
| 打开「回顾」（当天首次） | 按规则抽取并展示批次 | 不提供回顾入口 |
| 再次打开「回顾」（同一天） | 展示同一批次 | 不适用 |
| 调整规则并确认 | 当日批次作废，按新规则重抽 | 不适用 |
| 过零点后打开「回顾」 | 重新抽取 | 不适用 |

## 6. 验收标准

### AC-REQ-005-01 卡片流

给定一个含 Frontmatter、标签、无标题笔记与解析失败笔记的测试 Vault：

- iPhone 上首页为卡片流，按修改时间倒序；
- 无标题笔记显示文件名，解析失败笔记显示固定文案且不导致整页失败；
- 点卡片进入阅读面，返回后滚动位置与过滤状态保留；
- 紧凑宽度不出现「最近」「收藏」顶级入口，也不出现任何编辑入口。

### AC-REQ-005-02 每日回顾批次稳定

给定规则「含某标签、近三个月、8 条」且候选不少于 8 条：

- 当天第一次打开抽出 8 条；杀进程重开后顺序与成员不变；
- 将系统日期拨到下一天后重新抽取，允许与前一天不同；
- 候选只有 3 条时展示 3 条并显示「符合规则的只有 3 条」；
- 候选为空时显示空状态与「调整规则」。

### AC-REQ-005-03 抽取可复现

给定同一候选集、同一规则、同一本地日历日：

- 连续两次抽取（含清空批次后重抽）得到相同的有序路径列表；
- 换一个 Vault 标识后结果允许不同。

### AC-REQ-005-04 规则修改

- 选择「含标签」但未选标签时，完成按钮不可用；
- 确认修改规则后，当日批次按新规则重抽；取消后规则与批次都不变。

### AC-REQ-005-05 标签与搜索一致

- 过滤 `project` 的卡片集合与 Mac 端该标签的笔记集合一致，不包含仅标记 `project/mobile` 的笔记；
- 搜索结果与现有离线搜索一致，并以卡片呈现；空查询恢复时间倒序。

### AC-REQ-005-06 状态隔离与可重建

- 规则与批次写在 App 沙箱，不修改 Vault 中任何字节；
- 删除状态文件后笔记仍可浏览，回顾下次打开重新抽取；
- 切换 Vault 后看不到上一本的规则与批次。

### AC-REQ-005-07 平台隔离

- iPad 常规宽度仍为 REQ-001 三栏，不出现回顾入口；
- Mac App 的全部现有行为与测试保持不变；
- iOS 构建仍不包含编辑面源文件。

## 7. 非功能要求

- 卡片流与回顾只读已索引内容，断网可用；
- iCloud Drive 占位文件读取失败时沿用 REQ-004 的固定错误文案，单卡降级，不崩溃；
- 抽取在索引读取之后于内存完成，不新增数据库表；
- 日志不包含笔记正文。

## 8. 非目标

- 手机上新建、编辑、删除、重命名笔记；
- 间隔重复、记忆评分、「记住了 / 忘了」；
- 桌面小组件、推送通知、锁屏回顾；
- 随机漫步、相关笔记、统计与热力图；
- 图片画廊与附件渲染；
- 把回顾规则或批次同步到 Mac 或写回 Vault；
- 改变 iPad 三栏与 Mac 端信息结构。

## 9. 领域模型

限界上下文两个，笔记上下文沿用现有只读管线，回顾上下文是新增的纯逻辑。

### 9.1 卡片（值对象）

由 `IndexedNoteSummary` 投影，不持久化。字段：`path`、`title`、`excerpt`（preview 截断到 140 字符）、`tags`（完整标签身份，展示层限 3 个）、`modifiedAt`、`isReadable`（由 `parseStatus` 推导）。

### 9.2 回顾规则（值对象）

| 字段 | 类型 | 约束 |
|---|---|---|
| contentScope | 枚举 | `all` / `includingTag(String)` / `excludingTag(String)` / `untagged` |
| timeScope | 枚举 | `all` / `pastYear` / `pastSixMonths` / `pastThreeMonths` / `pastMonth` |
| dailyCount | 整数 | 4...24 且为 4 的倍数，默认 8 |

`includingTag` 与 `excludingTag` 的标签必须非空，否则规则不可提交。

### 9.3 当日批次（实体）

按 Vault 一份。字段：`vaultID`、`day`（本地日历日）、`ruleSnapshot`、`orderedPaths`。身份是 `vaultID + day`。规则变化时整条作废重抽，不原地修改成员。

### 9.4 关键业务流

打开回顾时：

1. 读取该 Vault 的规则；没有规则则进入规则设置，不抽卡。
2. 读取批次；若 `day` 是今天且 `ruleSnapshot` 与当前规则相等，直接返回。
3. 否则从索引取候选：先按时间范围过滤修改时间，再按内容范围过滤标签，解析失败的笔记不进入候选。
4. 用种子 `hash(vaultID, day, rule)` 对候选做稳定洗牌，取前 `dailyCount` 条。
5. 落盘批次；落盘失败则返回结果但标记未保存。

稳定洗牌要求确定：给定同一输入与同一种子，输出顺序固定。测试不绑定具体洗牌算法，只绑定这个性质。

## 10. 兼容性约束

- 不修改 `IndexedNoteSummary`、索引 schema、用户状态格式与任何既有端口协议；
- 卡片所需标签通过现有标签查询按路径获取，不新增索引列；
- 新增代码的平台条件编译只允许出现在 iOS 壳层文件内，不进入 Domain、Markdown、Index、LocalVault、UserState；
- 回顾逻辑放在纯逻辑类型中，不依赖 SwiftUI，便于单元测试；
- Mac 侧三栏、编辑与测试基线零变化。
