# REQ-004 iOS 只读客户端

## 1. 核心判断

值得做,但只做只读。iOS 端的价值是随时随地离线阅读已有 Vault,而不是复刻 Mac 的编辑能力。
写路径(编辑、上传、冲突)是数据丢失风险最高的部分,必须继续留在已验证的 Mac 侧;iOS 端在
第一版引入任何写路径,都会在没有 WebDAV 同步基线的情况下复制全部 M3/M4 的风险。

因此本需求固定两个边界:

1. **内容来源只有本地文件夹**:用户通过系统文件选择器选择本地或 iCloud Drive 中的 Vault
   文件夹;不引入 WebDAV 拉取。WebDAV 拉取栈属于 M2,未完成前 iOS 不自行建第二套同步。
2. **零写路径**:iOS target 不编译编辑面,不提供编辑、创建、删除、重命名或上传入口;
   整个产品流程不得修改 Vault 中的任何字节。

除以上边界外,iOS 只读客户端与 Mac 内部 P0(M1)保持能力对等:列表、最近、收藏、标签、
搜索、阅读和 Wiki Link 跳转,全部复用已验证的核心模块与端口。

## 2. 目标

- 用户在 iPhone 上选择 Vault 文件夹后,即可离线浏览、搜索和阅读笔记;
- 用户在 iPad 上获得与 Mac 相同职责的三栏布局;
- 全部交互复用 Mac 已验证的信息结构与选择语义,不建立第二套导航模型;
- 共享核心模块(Domain、Markdown、Index、LocalVault、UserState、Library Feature)不因
  iOS 而产生行为分叉;
- Mac 侧现有行为零变化。

## 3. 术语与信息结构

| 术语 | 定义 | 可承载内容 |
|---|---|---|
| 紧凑宽度导航 | iPhone 及 iPad 分屏下的推入式导航 | 固定五个顶级入口:笔记、最近、收藏、搜索、标签 |
| 常规宽度三栏 | iPad 常规宽度下的三栏布局 | 与 Mac 相同的"导航—笔记列表—详情"栏位职责 |
| Vault 选择 | 通过系统文件选择器选择文件夹并建立安全书签 | 本地文件夹或 iCloud Drive 中的 Vault 根目录 |
| 本机元数据 | App 沙箱内每个 Vault 的索引与用户状态 | `index.sqlite`、`user-state.json` |

> [!important] 平台不变量
> iOS 只读客户端不出现任何编辑入口:无"编辑"按钮、无编辑态、无命令、无第二编辑区域。
> 阅读面以 `editorSource == nil` 构造,编辑 UI 由编译期排除而不是运行时隐藏保证。

## 4. 功能需求

### 4.1 Vault 选择与恢复

1. 首次启动提供"打开 Vault…"入口,使用系统文件夹选择器只接受目录;本地与 iCloud Drive
   中的文件夹均可选择。
2. 选择后使用安全作用域书签持久化,下次启动自动恢复;书签失效时回到选择入口并说明原因。
3. iOS 创建书签时不使用 macOS 专属的安全作用域书签选项,平台差异只允许出现在该接缝处。
4. 每次选择使用独立 UUID,索引与用户状态保存在 App 沙箱内,与 Mac 侧数据互不影响。
5. 用户 Vault 始终只读;切换 Vault 不得复用旧索引或收藏。

### 4.2 紧凑宽度导航(iPhone)

1. 顶级结构固定为五个入口:笔记、最近、收藏、搜索、标签;每个入口是独立的导航栈。
2. 标签入口显示完整标签身份与计数;选择标签后推入精确匹配该标签的笔记列表,匹配规则与
   Mac 一致(完整标签身份精确匹配)。
3. 笔记、最近、收藏、搜索四个入口直接显示笔记列表;搜索入口含查询输入,空查询显示最近
   笔记,行为与 Mac 一致。
4. 从任一列表选择笔记后,推入阅读面;返回时不丢失列表滚动位置和筛选状态。
5. 加载、索引中、空结果和失败状态复用 Mac 的互斥状态建模与固定文案,不建立第二套状态。

### 4.3 常规宽度三栏(iPad)

1. 常规宽度下复用"导航—笔记列表—详情"三栏,栏位职责与
   [REQ-001](REQ-001-sidebar-navigation-and-note-list.md) 完全一致;
2. 紧凑宽度(含 iPad 分屏)自动切换为 4.2 的推入式导航,信息结构不变。

### 4.4 阅读与跳转

1. 阅读面复用 Reader:标题、段落、强调、列表、任务、引用、代码块和标准链接的渲染与
   Mac 保持一致;不支持语法安全降级为原文。
2. 已解析的 Wiki Link 可跳转到目标笔记并继续导航;缺失、歧义和非法链接不可跳转。
3. 标准外部链接交给系统打开。
4. 阅读历史(返回栈)由系统导航栈承载,不需要额外的最近阅读结构。

### 4.5 收藏

1. 收藏与取消收藏行为、持久化位置(App 沙箱)和失败降级与 Mac 一致。
2. 收藏状态保存在 iOS 设备本地,不与 Mac 同步。

### 4.6 索引与状态

1. 首次打开 Vault 时建立全量索引并展示"索引中"状态;之后增量索引只处理变化文件。
2. 断网不影响已索引内容的浏览、搜索和阅读;iCloud Drive 中的占位文件在读取失败时给出
   可理解的固定错误文案,不得崩溃或显示错误内容。

## 5. 交互映射

| 用户操作 | 紧凑宽度结果 | 常规宽度(iPad)结果 |
|---|---|---|
| 打开 App(已有 Vault 书签) | 直接进入"笔记"入口 | 直接进入三栏,保持上次目的地 |
| 选择"标签"中的某个标签 | 推入该标签的笔记列表 | 中栏显示该标签的笔记 |
| 从列表选择笔记 | 推入阅读面 | 详情栏显示该笔记 |
| 阅读中点击已解析 Wiki Link | 推入目标笔记 | 详情栏切换到目标笔记 |
| 返回 | 回到原列表,滚动位置保留 | 选择与列表保持不变 |
| 书签失效 | 回到 Vault 选择入口并说明 | 同左 |

## 6. 验收标准

### AC-REQ-004-01 Vault 选择与恢复

给定一台 iOS 设备和一个含 Frontmatter、标签、Wiki Link 与 Unicode 路径的测试 Vault:

- 用户可通过文件选择器选择 Vault 文件夹;重启 App 后自动恢复同一 Vault;
- 索引建立后可浏览、搜索和阅读;
- 整个流程不修改 Vault 中任何字节。

### AC-REQ-004-02 紧凑导航结构

在 iPhone 上依次使用笔记、最近、收藏、搜索、标签:

- 五个入口始终存在且职责与 Mac 对应入口一致;
- 不出现编辑入口、编辑菜单或任何写操作控件;
- 从阅读面返回后,原列表的筛选状态与滚动位置保留。

### AC-REQ-004-03 阅读与跳转

给定包含 `[[Note]]`、`[[Note|Alias]]`、歧义链接和外部链接的笔记:

- 已解析 Wiki Link 跳转到目标笔记,可连续跳转并逐级返回;
- 歧义和缺失链接不可跳转,以原文安全显示;
- 外部链接交给系统打开;
- 渲染结果与 Mac 对同一笔记的渲染一致。

### AC-REQ-004-04 搜索与标签

- 搜索标题、正文和标签离线可用,空查询显示最近笔记;
- 标签精确匹配语义与 Mac 一致:选择 `project` 不隐式包含仅标记 `project/mobile` 的笔记。

### AC-REQ-004-05 收藏

- 收藏操作即时反馈,失败时保留旧状态并显示固定文案;
- 重启后收藏状态保留;同一 Vault 在 Mac 与 iOS 上的收藏互不影响。

### AC-REQ-004-06 iPad 三栏

在 iPad 常规宽度下:

- 三栏职责与 [REQ-001](REQ-001-sidebar-navigation-and-note-list.md) 一致;
- 通过 REQ-001 的栏位稳定性验收(AC-REQ-001-03)的等价场景。

### AC-REQ-004-07 可访问性与外观

- Dynamic Type、VoiceOver、浅色与深色模式可用;选中状态不只依赖颜色。

### AC-REQ-004-08 平台隔离

- Mac App 的全部现有行为与测试保持不变;
- iOS 构建不包含编辑面源文件;iOS target 的只读属性由文件成员与编译期条件保证。

## 7. 兼容性与迁移约束

- 共享源码文件不得引入平台分叉,平台差异只允许出现在本需求记录的接缝:
  1. `ReaderView` 编辑分支的 `#if os(macOS)`;
  2. 编辑面三个文件(`ReaderInlineEditor`、`SourcePreservingTextView`、
     `EditorSurfaceLayoutManager`)整体 `#if os(macOS)` 守卫——Xcode iOS target 不加入
     成员,SPM 共享 target 在 iOS 下编译为空,保证两个构建体系行为一致;
  3. `VaultSelection` 书签创建/解析选项按平台分支;
  4. `AppEnvironment` 仅在 macOS 构造 `EditorDataSource`,iOS 为 `nil`;
  5. App 入口与壳层文件按平台分离(Mac `BearObsApp` + 三栏壳;iOS `BearObsIOSApp` +
     iOS 壳),SPM `BearObsAppShell` 排除 iOS 目录;
  6. iOS 的共享核心测试由 `BearObsIOSTests`(以只读 App 为宿主)在模拟器执行,其成员
     镜像 Mac 单元测试并排除三个编辑器测试文件;SPM 宿主测试继续全量执行;
- 其余共享文件不得出现平台条件编译;
- Mac 侧三栏、编辑与测试基线零变化;共享核心模块的测试在两个平台目的地都必须通过;
- 不修改 Vault 内容、索引 schema、用户状态格式和任何既有端口协议。

## 8. 非目标

- 编辑、创建、删除、重命名和上传;iOS 写路径待 Mac M3/M4 稳定后另行立项;
- WebDAV 拉取与同步状态;等 M2 完成后作为 iOS 二期复用;
- 图片和附件渲染(Mac 渲染器当前亦不支持,保持对等);
- 跨设备收藏、阅读进度同步;
- 小组件、快捷指令、后台刷新和通知;
- iPad 键盘快捷键与指针专项优化;
- 像素级复制任何参考产品。
