# REQ-001 主侧边栏标签导航与固定笔记列表

## 1. 核心判断

值得做。标签是“筛选笔记的导航条件”，不是一种需要占用笔记列表栏的内容。让标签列表和笔记列表轮流占用同一栏，会改变栏位语义，增加返回操作，并破坏用户对三栏布局的稳定预期。

本需求固定三栏职责：

1. **最左侧主侧边栏**：系统入口、标签树和当前筛选条件；
2. **次左侧笔记列表栏**：当前条件下的笔记列表；
3. **右侧详情栏**：当前选中笔记的阅读或编辑内容。

参考截图仅用于说明“标签直接出现在最左侧导航栏”的交互方式，不要求复制其品牌、图标、颜色、标签名称或像素级布局。

## 2. 目标

- 用户无需进入单独的“标签页”，即可在最左侧主侧边栏浏览并选择标签；
- 用户选择任意标签后，次左侧栏直接显示匹配的笔记；
- 无论选择全部笔记、最近、收藏、标签还是搜索，次左侧栏始终保持“笔记列表”这一职责；
- 降低栏位切换、返回标签列表和重新定位笔记造成的认知成本。

## 3. 术语与信息结构

| 术语 | 定义 | 可承载内容 |
|---|---|---|
| 主侧边栏 | 窗口最左侧导航栏 | 全部笔记、最近、收藏、搜索等系统入口，以及标签树 |
| 笔记列表栏 | 主侧边栏右侧的次左栏 | 笔记条目，以及该列表的加载、空、错误状态 |
| 详情栏 | 笔记列表栏右侧区域 | 选中笔记的阅读、编辑或未选择提示 |
| 标签树 | 按标签完整身份展示的层级导航 | 标签节点、展开/收起状态和选中状态 |

> [!important] 栏位不变量
> 笔记列表栏不得显示标签集合、标签管理页或“先选标签”的中间页面。标签选择必须发生在主侧边栏，选择结果必须直接作用于笔记列表栏。

## 4. 功能需求

### 4.1 主侧边栏

1. 主侧边栏必须同时容纳系统入口和标签导航，标签不得作为占用笔记列表栏的独立顶层页面。
2. 标签应位于可折叠的“标签”分组中；标签数量超过可视区域时，由主侧边栏自身滚动，不得把标签溢出到笔记列表栏。
3. 嵌套标签使用 `/` 表达层级，例如 `project/mobile` 在视觉上显示为 `project` 下的 `mobile`；底层标签身份仍使用完整规范化值。
4. 点击标签节点后，该节点成为当前筛选条件，笔记列表栏立即进入对应列表的加载或内容状态。
5. MVP 中标签筛选使用**完整标签身份精确匹配**。选择 `project` 不自动包含仅标记为 `project/mobile` 的笔记；包含后代标签必须作为独立需求提出，不能暗中改变查询语义。
6. 当前系统入口或标签必须有明确选中状态，并提供可访问性标签；状态不能只依赖颜色表达。

### 4.2 笔记列表栏

1. 笔记列表栏只展示 `IndexedNoteSummary` 语义的笔记集合，不展示标签集合。
2. 选择“全部笔记”时，显示全部可读取笔记；选择“最近”时，显示最近笔记；选择“收藏”时，显示收藏笔记；选择标签时，显示精确匹配该标签的笔记；执行搜索时，显示搜索命中的笔记。
3. 加载、索引中、空结果和失败提示属于笔记列表的状态，可以替换列表正文，但不得改变该栏的业务职责。
4. 切换筛选条件时，应取消或隔离旧请求，较慢的旧结果不得覆盖新筛选结果。
5. 筛选结果继续复用现有笔记摘要、稳定排序、错误降级和离线读取规则，不建立第二套笔记列表模型。

### 4.3 详情栏与选择连续性

1. 用户在笔记列表栏选择笔记后，详情栏显示该笔记。
2. 筛选条件变化后，如果当前笔记仍属于新结果，可保留当前选择；如果不属于新结果，清除选择并显示“选择一篇笔记”的空状态。
3. 切换筛选条件不得自动打开第一篇笔记，避免用户在未明确选择时误读或误编辑。

### 4.4 窗口与平台行为

1. 在 macOS 三栏布局可用时，三栏必须按“导航—笔记列表—详情”顺序排列。
2. 系统或用户可折叠栏位，但重新展开后栏位职责不得改变。
3. 窄窗口导致系统临时折叠栏位，不视为违反“笔记列表栏固定为笔记列表”；逻辑层级和恢复后的物理顺序必须保持不变。
4. 键盘导航、VoiceOver、浅色模式和深色模式必须保持相同的信息结构与选中语义。

## 5. 交互映射

| 用户操作 | 主侧边栏状态 | 笔记列表栏结果 | 详情栏结果 |
|---|---|---|---|
| 选择“全部笔记” | “全部笔记”选中 | 全部笔记 | 保留仍有效的选择，否则为空 |
| 选择“最近” | “最近”选中 | 最近笔记 | 保留仍有效的选择，否则为空 |
| 选择“收藏” | “收藏”选中 | 收藏笔记 | 保留仍有效的选择，否则为空 |
| 选择某个标签 | 对应标签选中 | 精确匹配该标签的笔记 | 保留仍有效的选择，否则为空 |
| 输入搜索条件 | 搜索入口选中 | 搜索命中的笔记 | 保留仍有效的选择，否则为空 |
| 标签无匹配笔记 | 对应标签仍选中 | “没有匹配的笔记” | 空状态 |
| 标签查询失败 | 对应标签仍选中 | 明确错误或保留的旧笔记结果及错误提示 | 不显示错误笔记 |

## 6. 验收标准

### AC-REQ-001-01 标签位置

给定应用以三栏布局展示，打开包含标签的 Vault：

- 所有可用标签可从最左侧主侧边栏访问；
- 次左侧栏不出现标签集合或标签选择页；
- 无需执行“返回所有标签”操作即可改选其他标签。

### AC-REQ-001-02 标签筛选

给定笔记 A 含标签 `project`，笔记 B 仅含标签 `project/mobile`：

- 选择 `project` 时，笔记列表显示 A，不因层级关系隐式加入 B；
- 选择 `project/mobile` 时，笔记列表显示 B；
- 两次操作都只更新次左侧笔记列表，不改变栏位职责。

### AC-REQ-001-03 栏位稳定性

依次切换全部笔记、最近、收藏、标签和搜索：

- 最左栏始终是导航与筛选；
- 次左栏始终是笔记列表或其加载、空、错误状态；
- 右栏始终是笔记详情或未选择状态。

### AC-REQ-001-04 异步与空状态

快速连续选择两个标签，并让第一个请求晚于第二个请求返回：

- 最终笔记列表只显示第二个标签的结果；
- 无匹配结果时显示笔记空状态，不能退回标签列表；
- 查询失败时提供可操作提示，且不能把错误结果显示为可打开笔记。

### AC-REQ-001-05 可访问性

- 键盘可在主侧边栏选择系统入口和标签，再进入笔记列表；
- VoiceOver 可读出标签名称、层级和选中状态；
- 选中状态在浅色与深色模式下均不只依赖颜色。

## 7. 兼容性与迁移约束

- 现有标签解析、规范化身份、计数和精确查询规则保持不变；本需求只改变标签导航所在栏位及交互流。
- 现有笔记列表、最近、收藏、搜索和 Reader 的数据接口应继续复用。
- 移除“中栏先显示标签、选中后再替换为笔记”的交互时，不得破坏深色模式、键盘导航、VoiceOver 或当前笔记读取路径。
- 本需求不要求修改 Vault 内容、Frontmatter 或 Inline Tag。

## 8. 非目标

- 不在本需求中增加标签创建、重命名、删除或拖拽整理；
- 不定义父标签自动包含所有子标签的聚合查询；
- 不复制参考产品的品牌、图标、颜色和标签分类；
- 不改变 Markdown 标签解析、索引或同步协议；
- 不要求在窄窗口中强制同时显示三栏。
