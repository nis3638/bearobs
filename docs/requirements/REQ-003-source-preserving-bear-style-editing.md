# REQ-003 Bear 式所见即所得与 Obsidian 无损编辑

## 1. 核心判断

值得做。Bear 式编辑体验和 Obsidian 语法兼容并不冲突；真正会破坏用户内容的，是把 Markdown 解析成富文本或抽象语法树后，再序列化并覆盖整篇文件。

本需求固定两个不可打破的不变量：

> [!important] 内容事实源不变量
> Vault 中的原始 Markdown 字节始终是内容事实源。渲染树、富文本状态、索引和编辑节点都是派生数据，不得反向取代原文。

> [!important] 最小改写不变量
> 保存时只能改写用户实际编辑所对应的源码区间。未编辑字节必须保持不变；不得为了获得统一排版而重新序列化整篇 Markdown。

参考 Bear 的范围是编辑即预览、低干扰语法呈现和块级视觉连续性；不复制 Bear 的私有文件格式、品牌、图标、颜色、文案或像素级布局。

## 2. 目标

- 在 REQ-002 的原详情栏中提供接近 Bear 的编辑即预览体验；
- 标题、段落、强调、列表、任务项、引用、代码和链接尽可能按最终阅读效果显示并直接编辑；
- 保证未编辑的 Frontmatter、空白、换行、注释及 Obsidian 或插件语法字节级不变；
- 让系统在不理解某种语法时安全降级，而不是猜测、删除、格式化或重排；
- 通过源码区间和最小补丁统一结构化编辑、原始文本编辑与现有原子保存路径；
- 为语法扩展、自动化测试和兼容性回归建立明确契约。

## 3. 术语与数据关系

| 术语 | 定义 |
|---|---|
| 原始 Markdown | 从当前笔记文件读取的完整字节序列，是唯一内容事实源 |
| 源码区间 | 编辑或渲染节点在原始 UTF-8 字节序列中的半开区间 |
| 结构化节点 | 编辑器已理解其语义、源码边界和安全改写规则的内容节点 |
| 不透明节点 | 编辑器不能安全结构化修改、但必须完整保留的原始语法区间 |
| 最小源码补丁 | 对一个或多个互不重叠源码区间执行的替换操作 |
| 派生文档 | 由原文解析出的渲染树、编辑树、索引数据和可访问性语义 |
| 基线快照 | 编辑开始或上次成功保存后对应的原始字节、内容哈希和源码映射 |
| 局部源码模式 | 只显示并编辑目标不透明节点原文的安全降级模式，不替换整篇编辑界面 |

数据流必须保持单向：

```text
原始 Markdown 字节
    ↓ 保留精确源码区间的解析
结构化节点 + 不透明节点
    ↓ 用户编辑
最小源码补丁
    ↓ 基线哈希校验与原子保存
新的原始 Markdown 字节
```

以下关系必须成立：

- 原始 Markdown 拥有所有持久化内容；
- 结构化节点只引用源码区间，不拥有第二份可独立保存的文档；
- 不透明节点拥有可显示的原始文本，但系统不得擅自解释或改写；
- 补丁只描述用户修改，不描述全文重新排版；
- 保存结果必须重新解析并建立新基线，旧节点和旧源码区间不得继续写入新版本。

## 4. 功能需求

### 4.1 保留源码的解析

1. 编辑解析结果必须为每个可编辑节点保留精确的 UTF-8 源码区间。
2. 源码区间必须相对于同一份基线字节计算，不能混用 Unicode 字符位置、Swift `String.Index`、UTF-16 位置或渲染后的文本位置。
3. 节点嵌套、行尾、缩进、列表标记和任务标记必须有明确边界；无法证明边界正确时必须降级为不透明节点。
4. 重叠、越界、无效 UTF-8 映射或无法与原文核对的节点不得进入结构化写入路径。
5. 解析失败必须局部降级；除文件本身不可安全读取外，不得因为一个未知节点阻止整篇笔记阅读。

### 4.2 编辑即预览表面

1. REQ-002 的同一详情栏继续承载阅读态和编辑态，不得另建第二编辑容器。
2. 已支持的标题、段落、强调、列表、任务列表、引用、代码和链接应尽可能按阅读态排版直接编辑。
3. Markdown 标记可在非焦点状态下降低干扰或隐藏，但获得焦点时必须能恢复足够的源码语义，避免用户无法理解实际保存内容。
4. 隐藏语法不得改变源码；视觉隐藏、语义渲染和持久化必须是三个独立层次。
5. 编辑器必须保持当前块、插入点、选择和滚动上下文；重新解析不得无条件把焦点移到全文开头。
6. 用户必须能够识别当前处于编辑态、当前可编辑区域以及保存状态；焦点不得只依赖颜色表达。

### 4.3 最小源码补丁

1. 每次结构化修改必须转换为针对基线源码区间的最小补丁。
2. 多个补丁必须互不重叠，并按不会导致后续区间偏移失效的确定顺序应用。
3. 修改普通段落时，只能替换该段落对应的源码区间；相邻空行、注释、Frontmatter 和未知语法不得变化。
4. 勾选任务项时，只能修改对应任务标记的语义字节，例如把 `[ ]` 改为 `[x]`；不得重排整个列表。
5. 修改标题层级时，只能修改标题标记及用户实际编辑的标题内容；不得格式化全文其他标题。
6. 修改链接显示文本或目标时，只能修改对应链接源码；Wiki Link、Markdown Link 和外部链接不得互相自动转换。
7. 没有用户内容修改时，保存结果必须与基线字节完全一致，不得产生格式化写入。
8. 补丁应用后必须重新校验完整结果可按原文件编码约定保存，并建立新的内容哈希和源码映射。

### 4.4 Obsidian 语法兼容与降级

以下内容即使暂不支持结构化编辑，也必须完整保留：

- Frontmatter，包括字段顺序、类型、注释、引号风格和未知字段；
- Wiki Link，例如 `[[目标]]`、`[[目标|别名]]` 和 `[[目标#^block-id]]`；
- Embed，例如 `![[图片.png|300]]` 和 `![[笔记#标题]]`；
- Callout，例如 `> [!note]`、折叠标记、自定义标题和嵌套内容；
- Block ID，例如 `^block-id`；
- Obsidian 注释、转义、标签、脚注、数学公式、HTML 和属性语法；
- Dataview、Query 及其他插件代码块；
- 编辑器未知或未来新增的 Obsidian 与插件语法。

降级规则如下：

1. 能安全渲染但不能结构化修改的节点，可以显示预览，并在编辑时进入该节点的局部源码模式。
2. 既不能安全渲染也不能结构化修改的节点，必须以可读原文显示，不能隐藏或丢弃。
3. 局部源码模式只能编辑目标节点的原始区间，不得切换为脱离上下文的全文源码编辑器。
4. 未进入编辑的未知节点保存前后必须字节级一致。
5. 系统不得为了统一外观，把 Wiki Link 转成 Markdown Link、把 Callout 转成普通引用或把插件语法转成普通代码块。

### 4.5 保存、并发与重新解析

1. 本需求复用 FR-09 与 REQ-002 的草稿、基线哈希、本地原子替换、索引刷新和同步安排，不建立第二套保存路径。
2. 保存前必须验证当前文件内容哈希仍与编辑基线一致；如果外部程序已修改文件，必须停止写入并进入现有冲突或重载流程。
3. 保存期间发生的新输入不得被较早补丁结果覆盖。
4. 保存成功后必须从新原文重新解析并发布新节点映射；旧异步解析结果不得覆盖新版本。
5. 保存失败时必须保留当前草稿、补丁和焦点，并允许用户重试或复制内容。
6. 切换笔记、关闭窗口、执行 `Escape` 或离开详情栏不得绕过未保存修改保护。

### 4.6 预览安全

1. 预览只能消费派生渲染数据，不能触发文件改写。
2. HTML、脚本、自定义 URI 和插件内容不得因为预览而获得任意代码执行或任意系统动作能力。
3. 外部链接、内部 Wiki Link 和附件继续服从现有路由、路径和协议白名单。
4. 预览失败只能影响目标节点展示，不得删除原文或阻止用户进入安全的局部源码模式。

### 4.7 键盘与可访问性

1. 用户必须能通过键盘进入编辑、在结构化节点和不透明节点之间导航、保存并退出编辑。
2. VoiceOver 必须能读出节点类型、编辑状态、链接或任务语义、保存状态和错误状态。
3. 被视觉隐藏的 Markdown 标记不能导致辅助技术丢失必要语义。
4. 局部源码模式必须明确朗读其作用范围，避免用户误以为正在编辑整篇文档。

## 5. 验收标准

### AC-REQ-003-01 无修改保存保持字节一致

给定一篇包含 BOM、CRLF、Frontmatter、注释和未知插件语法的笔记：

- 进入编辑态后不修改内容并执行保存，不产生文件改写；
- 保存前后的完整字节序列一致；
- 文件修改时间不得仅因进入或退出编辑态而变化。

### AC-REQ-003-02 普通段落最小改写

给定一个普通段落前后存在 Frontmatter、空白、Callout 和 Dataview 代码块：

- 只修改普通段落中的一个词并保存；
- 只有目标段落对应源码区间发生预期变化；
- Frontmatter、空白、Callout、Dataview 及换行约定保持字节级不变。

### AC-REQ-003-03 任务项和列表语义

给定包含不同缩进、不同列表标记和任务项的笔记：

- 勾选一个任务项只修改该任务标记；
- 列表标记、缩进、相邻任务和 Block ID 不被重排；
- Obsidian 重新读取后任务语义正确。

### AC-REQ-003-04 未知语法安全降级

给定编辑器不认识的 Obsidian 或插件语法：

- 节点以预览或可读原文显示，不消失；
- 用户可在该节点范围内进入局部源码模式；
- 修改其他节点并保存后，未知节点字节级不变；
- 系统不会把未知节点转换成自认为等价的标准 Markdown。

### AC-REQ-003-05 Wiki Link、Embed 与 Callout 保真

给定笔记包含别名 Wiki Link、块引用、Embed、折叠 Callout 和嵌套 Callout：

- 预览能安全显示已支持语义；
- 修改相邻普通文本不会改变这些语法；
- 未明确编辑链接目标时，链接或 Embed 的原始写法保持不变；
- 保存后 Obsidian 中的跳转、嵌入和 Callout 语义与保存前一致。

### AC-REQ-003-06 外部修改与并发输入

给定编辑期间文件被 Obsidian 或同步流程修改，或者保存期间用户继续输入：

- 基线哈希不一致时拒绝覆盖外部修改；
- 用户草稿和最小补丁被保留并可复制或合并；
- 较早保存结果不会覆盖保存期间的新输入；
- 旧解析结果不会污染新笔记或新版本。

### AC-REQ-003-07 编辑即预览与可访问性

- 已支持节点在原详情栏按接近阅读态的排版直接编辑；
- Markdown 标记的视觉隐藏不会修改文件内容；
- 键盘和 VoiceOver 能识别结构化节点、不透明节点、局部源码模式和保存状态；
- 浅色与深色模式下，编辑焦点和错误状态均不只依赖颜色表达。

## 6. 兼容性与迁移约束

- 现有原始 Markdown 编辑器应保留为安全兜底和诊断入口，不能在结构化编辑未覆盖全部语法前删除。
- 现有 `EditorFeatureModel` 的草稿、基线哈希、保存竞态保护和错误语义继续复用。
- 现有 `MarkdownNoteParser`、Reader 渲染模型和索引可以逐步增加源码区间，但不能因此改变旧文件的解析兼容行为。
- 新编辑树必须是可丢弃、可重建的派生状态，不得建立独立于 Markdown 文件的持久化内容数据库。
- 本需求不得改变 VaultPath、同步基线、WebDAV 条件写入和冲突规则。
- 任何新增语法支持都必须先提供“未编辑区间保持字节一致”的回归样本，再进入默认结构化编辑路径。

## 7. 非目标

- 不要求首个版本结构化编辑全部 Obsidian 或插件语法；
- 不要求复制 Bear 的私有编辑器实现、动画、品牌或专有格式；
- 不把 Markdown 转换为 HTML、RTF、富文本数据库或 Bear 专有格式作为新的事实源；
- 不在本需求中增加多人实时协作、笔记创建、删除或重命名；
- 不承诺任意第三方插件都能获得专用视觉编辑器；未知插件语法首先保证保真和可恢复；
- 不允许用“格式化后语义等价”替代未编辑字节保持不变的要求。
