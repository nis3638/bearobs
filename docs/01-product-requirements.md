## 2. 问题陈述

已有 Obsidian Vault 的用户希望在 Mac 上获得快速、安静、适合高频使用的笔记体验，但又不愿把内容迁移到封闭格式或另一个云服务。现有方案通常在两端失衡：

- 兼容 Obsidian 文件，但桌面端浏览和编辑体验不够好；
- 编辑体验优秀，但笔记被锁定在私有格式或专有同步服务中。

BearObs 要解决的是真实桌面场景：快速查找、离线阅读、低延迟编辑，并通过 WebDAV 安全地与既有 Vault 交换文件。最大产品风险不是界面不像 Bear，而是同步错误造成笔记被覆盖或丢失。

## 3. 产品定义

BearObs 是一个本地优先的 macOS 原生 Obsidian Vault 客户端：

- 以 Vault 中的 Markdown 和附件为内容事实源；
- 提供受 Bear 和 Apple Notes 启发的信息架构与交互效率；
- 使用本地工作副本保证离线可用；
- 使用可重建索引保证列表、标签和搜索性能；
- 通过 WebDAV 下载和上传文件；
- 不复制 Bear 的品牌、图标、文案或视觉资产。

一句话定义：

> 用接近 Bear 的桌面体验，安全地浏览和编辑 Obsidian Vault。

## 4. 核心原则

1. **内容开放**：不创建只有 BearObs 才能读取的笔记格式。
2. **Vault 优先**：Markdown 和附件是内容事实源，索引不是。
3. **本地优先**：已同步内容在断网时仍可阅读、搜索和编辑。
4. **不静默覆盖**：本地与远端同时变化时必须进入显式冲突。
5. **最小改写**：保存笔记不得无关地重排 Frontmatter 或格式化全文。
6. **可恢复**：内容索引损坏或被删除后能够从本地工作副本重建。
7. **确定性优先**：启动、窗口激活、手动刷新和保存后同步是确定触发点；后台同步不作为首发承诺。
8. **范围克制**：先交付可靠的笔记闭环，再增加创建、删除、重命名和高级 Obsidian 能力。

## 5. 已确认的产品决策

| 编号 | 决策 | 结论 |
|---|---|---|
| D-01 | 版本分层 | Mac 内部 P0 为本地只读纵切；Mac 技术预览支持 WebDAV 拉取；Mac 对外 MVP 支持编辑现有笔记、上传和冲突保护；iOS 只读客户端（本地文件夹来源，见 REQ-004）提前插入当前计划，iOS 写路径与同步仍后置 |

| D-04 | WebDAV 安全 | 只允许 HTTPS 和系统信任证书；不支持明文 HTTP 或跳过证书验证 |
| D-05 | 规模基线 | 10,000 个 Markdown 文件、2 GB 附件；Markdown 全量离线，附件按需缓存，单附件默认上限 50 MB |
| D-06 | 文件操作 | MVP 只编辑已有笔记；不提供 App 内创建、删除和重命名，但可接收远端变化 |
| D-07 | 三栏职责 | 最左侧主侧边栏承载系统入口与标签导航；次左侧栏固定为当前条件下的笔记列表；右侧栏承载笔记详情 |
| D-08 | 编辑交互 | 采用 Bear 式原位编辑：阅读态与编辑态共用当前笔记详情栏，不弹出独立编辑框、浮层或新窗口 |
| D-09 | 编辑保真 | 原始 Markdown 字节是唯一内容事实源；结构化编辑只生成最小源码补丁，禁止整篇 AST 序列化回写，未知语法按不透明节点保留 |

待定但不阻塞文档生成：

- 首个真实 WebDAV 认证服务已选定为坚果云，真实认证能力移交 M2-A6 在专用测试目录中验证，不阻塞内部 P0 的本地只读纵切；其他 RFC 4918 服务按兼容能力提供支持，不承诺未经测试的厂商行为。

## 6. 目标用户与场景

### 6.1 目标用户

- 已有 Obsidian Vault，并以 Markdown 作为长期知识资产的个人用户；
- 需要在 Mac 上快速查找、阅读和修改笔记的高频记录者；
- 使用自建或第三方 WebDAV 保存 Vault 的用户；
- 重视离线能力、数据可迁移性和内容安全的用户。

### 6.2 核心场景

1. 断网时搜索并阅读已同步笔记。
2. 从标签或最近列表快速找到一篇笔记。
3. 打开 Wiki Link 跳转到另一篇笔记。
4. 阅读包含本地图片引用的 Markdown。
5. 修改已有笔记并在网络恢复后安全上传。
6. Mac 与另一设备同时修改同一文件后，看到明确冲突并选择处理方式。
7. 远端新增、删除或重命名文件后，Mac 刷新得到一致结果。
8. 清理附件缓存而不影响 Markdown 和远端 Vault。

## 7. 产品范围

### 7.1 内部 P0

- 导入测试用本地 Vault；
- 笔记列表、最近排序和阅读；
- Frontmatter 标签与 Inline Tag 解析；
- 本地全文搜索；
- Wiki Link 跳转；
- 本机收藏；
- 可重建索引。

P0 不对外发布，不代表完整产品承诺。

### 7.2 WebDAV 技术预览

- 配置 HTTPS WebDAV；
- 首次扫描和 Markdown 下载；
- 增量拉取远端新增、修改和删除；
- 图片和附件按需下载；
- 离线阅读；
- 同步状态和可恢复错误。

技术预览是拉取型验证，不开放不安全的写路径。

### 7.3 对外 MVP

在技术预览基础上增加：

- 编辑已有 Markdown；
- 本地原子保存；
- 条件上传；
- 本地、远端和同步基线三方比较；
- 冲突保留双方；
- 冲突列表和显式解决；
- 发布所需的安全、性能、可访问性和隐私基线。

### 7.4 iOS 只读客户端（插队纵切）

与 Mac MVP 并行插入的只读纵切，详细要求见 [REQ-004](requirements/REQ-004-ios-read-only-client.md)：

- 内容来源为用户通过文件选择器选择的本地或 iCloud Drive Vault 文件夹，不含 WebDAV；
- 复用 Mac 已验证的列表、最近、收藏、标签、搜索、阅读和 Wiki Link 能力；
- iPhone 紧凑导航与 iPad 三栏；
- 不含编辑、上传、同步和任何写路径。

## 8. 用户故事

1. 作为已有 Vault 的用户，我希望连接 WebDAV 目录，以便不迁移内容就开始使用。
2. 作为重视安全的用户，我希望凭据保存在 Keychain，以便密码不会出现在普通配置和日志中。
3. 作为首次使用者，我希望连接测试能明确指出 URL、认证、证书或路径问题，以便快速修正配置。
4. 作为大型 Vault 用户，我希望首次同步有进度和可重试状态，以便知道系统没有卡死。
5. 作为 Mac 用户，我希望启动后先看到本地内容，以便网络状态不阻塞使用。
6. 作为笔记用户，我希望按最近修改时间浏览笔记，以便快速回到近期工作。
7. 作为笔记用户，我希望收藏常用笔记，以便从固定入口访问。
8. 作为 Obsidian 用户，我希望 Frontmatter 和正文中的标签都能被识别，以便沿用现有分类。
9. 作为 Obsidian 用户，我希望嵌套标签保持完整，以便 `#project/mobile` 不被错误拆散。
10. 作为知识库用户，我希望搜索标题、正文和标签，以便快速定位内容。
11. 作为离线用户，我希望断网时搜索已同步 Markdown，以便仍可工作。
12. 作为阅读者，我希望正确显示标题、强调、列表、引用、代码块和链接，以便内容可读。
13. 作为 Obsidian 用户，我希望点击 `[[Wiki Link]]` 跳转到目标笔记，以便沿用知识网络。
14. 作为 Obsidian 用户，我希望无法唯一解析的链接被明确标记，以免跳到错误文件。
15. 作为阅读者，我希望 `![[image.png]]` 能显示本地或缓存图片，以便笔记上下文完整。
16. 作为存储敏感用户，我希望附件按需下载并可清理缓存，以便控制设备空间。
17. 作为编辑者，我希望修改已有 Markdown 并本地保存，以便离线记录变化。
18. 作为编辑者，我希望保存只改变我编辑的内容，以免无关 Frontmatter 和换行被重写。
19. 作为编辑者，我希望网络恢复后自动尝试上传，以便减少手动操作。
20. 作为谨慎用户，我希望上传前确认远端版本未变化，以免覆盖桌面端修改。
21. 作为发生冲突的用户，我希望同时保留本地版和远端版，以便没有内容丢失。
22. 作为发生冲突的用户，我希望选择保留本地、保留远端或手工合并，以便恢复到期望状态。
23. 作为同步用户，我希望看到最近同步时间、当前状态和可操作错误，以便理解系统行为。
24. 作为隐私敏感用户，我希望日志不包含笔记正文、密码或完整认证信息，以免泄露知识资产。
25. 作为使用辅助功能的用户，我希望界面支持 Dynamic Type、VoiceOver 和深色模式，以便正常使用。
26. 作为长期用户，我希望索引可以安全重建，以便数据库损坏不影响原始笔记。
27. 作为多端用户，我希望远端删除和重命名在刷新后反映到 Mac，以便本地视图不长期漂移。
28. 作为用户，我希望后台同步失败不影响本地保存，以便系统调度不会阻塞记录。
29. 作为使用标签查找笔记的用户，我希望直接在最左侧主侧边栏选择标签，并让次左侧栏始终显示匹配的笔记列表，以便无需在标签页和笔记列表之间往返。
30. 作为编辑者，我希望点击编辑后直接在当前笔记显示栏中修改内容，以便不离开阅读上下文，也不被独立编辑框打断。
31. 作为希望在 iPhone/iPad 上查阅知识库的用户，我希望选择 Vault 文件夹后离线浏览、搜索和阅读笔记，以便不在 Mac 旁也能随时查阅内容。

## 9. 功能需求

### FR-01 Vault 连接

- 用户可输入服务 URL、用户名、密码和 Vault 路径。
- 系统只接受 `https://` URL。
- 系统通过 WebDAV 能力和目录访问检查验证配置。
- 凭据只写入 Keychain；普通配置只保存非敏感标识。
- 连接失败必须区分网络、TLS、认证、路径不存在、权限和服务不兼容。

### FR-02 首次同步

- 系统递归扫描 Vault，但不得跟随越出 Vault 根目录的路径。
- Markdown 全量下载到本地工作副本。
- 附件只记录远端元数据，首次阅读时按需下载。
- 同步可取消、可重试，重新执行不得重复或破坏已完成文件。
- 首次同步完成后建立本地索引。

### FR-03 增量同步

- 远端变化检测优先使用 `ETag`，并结合 `Last-Modified` 与 `Content-Length`；不得假设 WebDAV 提供内容 hash。
- 系统以同步基线、本地状态和远端状态进行三方决策。
- 远端单边修改下载，本地单边修改上传，双边修改进入冲突。
- 远端删除只在本地未修改时删除本地工作副本；本地已修改时进入冲突。
- 远端重命名在 MVP 中按“旧路径删除 + 新路径新增”处理。
- 同步触发点包括启动、窗口激活、手动刷新和编辑保存后。
- 首发版本不向用户承诺实时后台同步；后台调度只能作为后续优化。

### FR-04 笔记列表与导航

- 最左侧主侧边栏提供全部笔记、最近、收藏、搜索和标签导航；标签直接在该栏展示和选择。
- 次左侧栏固定展示当前入口或筛选条件对应的笔记列表，不得被标签集合或标签管理页替换。
- 右侧栏展示当前选中笔记；三栏职责固定为“导航与筛选—笔记列表—笔记详情”。
- 默认按本地已知修改时间倒序排列。
- 列表项展示标题、摘要、修改时间和同步异常标记。
- 空状态、加载状态、索引中状态和错误状态必须明确。
- 详细交互、兼容性边界和验收标准见 [REQ-001](requirements/REQ-001-sidebar-navigation-and-note-list.md)。

### FR-05 标签

- 支持 YAML Frontmatter 中字符串、数组形式的 `tags`。
- 支持正文 Inline Tag，例如 `#AI` 和 `#project/mobile`。
- 代码块、行内代码和 URL 片段中的 `#` 不得被误识别为标签。
- 标签大小写展示保留原文，查询规则在技术设计中统一。

### FR-06 搜索

- 搜索范围包括标题、正文和标签。
- 搜索结果展示匹配摘要并可跳转到笔记。
- 搜索必须离线可用。
- 空查询显示最近笔记，不执行无意义全表检索。

### FR-07 Markdown 阅读

- 支持标题、段落、粗体、斜体、删除线、列表、任务列表、引用、行内代码、代码块和标准链接。
- 支持 `[[Note]]`、`[[Note|Alias]]` 和 `![[attachment]]` 的 MVP 解析。
- Wiki Link 无唯一目标时不得任意跳转。
- 不支持的 Obsidian 语法以原文安全显示，不应导致整篇笔记无法打开。

### FR-08 收藏

- 用户可收藏或取消收藏已有笔记。
- 收藏状态保存在 App 沙箱的独立用户状态中。
- MVP 不把收藏写入 Markdown 或 Vault 隐藏目录。
- 远端重命名按路径身份处理，旧路径收藏失效并从有效收藏列表移除。

### FR-09 编辑与本地保存

- MVP 只允许编辑已有 Markdown 文件。
- 编辑入口和交互形态遵循 FR-14；底层持久化内容仍为标准 Markdown。
- 本地保存必须使用临时文件和原子替换。
- 保存失败不得破坏上一个可读取版本。
- 保存后立即更新对应索引并安排同步。
- UTF-8 BOM 和原始换行风格应在可识别时保留。

### FR-10 上传

- 更新已有远端文件时使用条件请求，优先基于最后已知 `ETag`。
- 远端版本不满足条件时停止写入并创建冲突。
- 网络失败保留本地修改并进入可重试状态。
- 自动重试必须有上限和退避，不得形成无限请求循环。

### FR-11 冲突处理

- 冲突产生时分别保存本地版本和远端版本。
- 冲突状态必须在列表和详情中可见。
- 用户可选择保留本地、保留远端或手工合并。
- 解决前不得自动覆盖任一版本。
- 冲突解决操作必须再次检查远端条件，避免解决过程中发生二次覆盖。

### FR-12 附件缓存

- 图片和附件按需下载。
- 单附件默认上限为 50 MB，超限时提示用户而不是静默失败。
- 用户可查看缓存占用并清理附件缓存。
- 清缓存不得删除 Markdown、本地未同步修改或同步账本。

### FR-13 状态与恢复

- 展示最近成功同步时间和当前同步状态。
- 错误信息必须包含用户可执行的下一步。
- 内容索引可由本地工作副本全量重建。
- 同步账本丢失时进入保守恢复流程，不得直接上传或删除远端文件。

### FR-14 Bear 式笔记原位编辑

- 用户点击笔记详情栏中的“编辑”后，当前详情栏直接从阅读态进入编辑态；不得弹出独立编辑框、模态窗口、浮层、新窗口或并列的第二编辑区域。
- 编辑态沿用当前选中的笔记及详情栏布局，标题、正文、列表、任务项等内容在原显示位置直接可编辑，不切换到独立的原始 Markdown 文本框。
- 进入编辑态时保留当前滚动位置，不得跳回笔记顶部；编辑焦点和插入光标必须清晰可见。
- 阅读态与编辑态应尽量保持一致的排版和尺寸，状态切换不得造成明显的内容位移或布局闪烁。
- 编辑完成后仍在同一详情栏中显示结果，并按照 FR-09 执行原子保存、索引更新和同步安排。
- 原位编辑只改变交互层，不改变内容事实源：保存结果仍为标准 Markdown，未编辑内容、Frontmatter、未知语法和换行约定不得被无关改写。
- 详细状态转换、异常处理、兼容性边界和验收标准见 [REQ-002](requirements/REQ-002-bear-style-inline-note-editing.md)。

### FR-15 Bear 式所见即所得与源码保真

- 已支持的标题、段落、强调、列表、任务项、引用、代码和链接应在 REQ-002 的原详情栏中按接近阅读态的排版直接编辑。
- Vault 中的原始 Markdown 字节始终是内容事实源；渲染树、编辑树、富文本状态和索引均为可重建派生数据。
- 每个结构化编辑节点必须保留精确 UTF-8 源码区间；用户修改必须转换为针对基线的最小源码补丁。
- 未编辑的 Frontmatter、空白、换行、注释、Wiki Link、Embed、Callout、Block ID 和未知插件语法必须保持字节级不变。
- 无法安全结构化编辑的语法必须降级为不透明节点，并可在原位置进入局部源码模式；不得删除、猜测、格式化或转换为其他语法。
- 保存继续复用 FR-09 的内容哈希前置条件、原子替换、索引刷新和同步安排；禁止把 AST 或富文本重新序列化为整篇 Markdown。
- 详细数据关系、降级规则、最小补丁契约和验收标准见 [REQ-003](requirements/REQ-003-source-preserving-bear-style-editing.md)。

## 10. 非功能要求

### NFR-01 数据完整性

- 已知和故障注入场景中，静默覆盖路径数量必须为 0。
- 本地写入在崩溃、磁盘不足和进程终止模拟下保留旧版本或完整新版本，不得留下半文件。
- 冲突必须保留双方可读取副本。

### NFR-02 兼容性

- 内容文件保持标准 Markdown。
- 未编辑的 Frontmatter 字段不得重排、删除或类型变化。
- 解析失败必须局部降级，不得阻止原文阅读。
- 文件路径支持 Unicode；路径比较和编码规则必须统一。

### NFR-03 性能

验收设备以项目选定的 macOS 15+ Mac 为准，测试 Vault 为 10,000 个 Markdown 文件：

- 已有本地索引时，冷启动至可操作列表的 P95 不高于 2 秒。
- 本地搜索首批结果的 P95 不高于 300 毫秒。
- 打开不超过 1 MB 的已缓存 Markdown，正文可滚动显示的 P95 不高于 500 毫秒。
- 增量索引只处理发生变化的文件，不得每次启动重建全库。
- 2 GB 附件不在启动时全量读入内存或下载。

首次远端扫描受网络和服务端性能影响，不设置脱离测试环境的绝对时限，但必须持续展示进度且允许恢复。

### NFR-04 安全与隐私

- 仅支持 HTTPS 和系统信任证书。
- 凭据保存在 Keychain。
- 对所有远端路径进行规范化，拒绝绝对路径、`..` 越界和非法重定向。
- 日志不记录密码、认证头、笔记正文或附件内容。
- 发布前 Critical 和 High 安全问题必须为 0。

### NFR-05 可用性与可访问性

- 支持深色模式、Dynamic Type 和 VoiceOver。
- 关键操作不能只依赖颜色表达状态。
- 同步错误、冲突和离线状态必须可理解且可恢复。

### NFR-06 可测试性

- 同步决策必须是无网络、无 UI 依赖的纯逻辑测试接缝。
- Markdown 元数据提取、路径解析和链接解析可独立测试。
- 核心领域与同步逻辑的行覆盖率和分支覆盖率均不低于 80%。
- 关键用户流程具备集成测试和 macOS UI 自动化测试。

## 11. 验收标准

### AC-01 本地只读纵切

给定包含 Frontmatter、Inline Tag、同名 Wiki Link、Unicode 路径和图片的测试 Vault：

- App 可枚举、索引、搜索和阅读 Markdown；
- 删除索引后可重建出等价结果；
- 整个过程不修改 Vault 中任何字节。

### AC-02 首次 WebDAV 同步

给定有效 HTTPS WebDAV 配置：

- App 可扫描并下载全部 Markdown；
- 附件只建立元数据，打开时才下载；
- 中断后重试不会重复或损坏文件；
- 凭据不出现在配置文件和日志中。

### AC-03 增量拉取

给定远端单边新增、修改、删除和重命名：

- 刷新后本地工作副本和索引反映远端状态；
- 远端重命名按删除加新增处理；
- 本地未修改文件可安全更新；
- 本地已修改文件不被远端变化覆盖。

### AC-04 编辑与上传

给定远端未变化的已有笔记：

- 用户可离线编辑并本地原子保存；
- 网络恢复后条件上传成功；
- 再次同步后本地、远端和基线一致；
- 未编辑 Frontmatter 和换行约定不被无关改写。

### AC-05 冲突

给定本地与远端自同一基线后都发生修改：

- 自动同步不覆盖任何一方；
- App 保存两个可读取版本并显示冲突；
- 用户可选择处理方式；
- 解决时若远端再次变化，系统创建新冲突而不是覆盖。

### AC-06 离线

给定已经完成首次同步且设备断网：

- 用户可浏览、搜索、阅读和编辑已同步 Markdown；
- 保存成功并标记待同步；
- 网络错误不阻塞本地内容访问。

### AC-07 性能与规模

给定 10,000 个 Markdown 和 2 GB 附件测试集：

- 满足 NFR-03 的本地性能预算；
- 启动和搜索无明显主线程长时间阻塞；
- 附件采用有界缓存，不发生全量预载。

### AC-08 主侧边栏标签导航与固定笔记列表

给定包含多个普通标签和嵌套标签的 Vault，并以三栏布局打开应用：

- 标签可直接从最左侧主侧边栏访问和选择；
- 选择标签后，次左侧栏直接显示精确匹配该标签的笔记；
- 依次切换全部笔记、最近、收藏、标签和搜索时，次左侧栏始终保持笔记列表职责；
- 右侧栏只显示选中笔记或未选择状态；
- 详细场景通过 [REQ-001](requirements/REQ-001-sidebar-navigation-and-note-list.md) 中的验收标准。

### AC-09 Bear 式笔记原位编辑

给定用户已在详情栏中打开一篇可编辑笔记，并滚动到正文中部：

- 点击“编辑”后，原详情栏直接进入编辑态，界面不出现独立编辑框、模态窗口、浮层、新窗口或第二编辑区域；
- 当前笔记、滚动位置和内容排版保持稳定，正文不会跳回顶部；
- 用户可在原显示位置看到插入光标，并直接修改标题、正文、列表和任务项；
- 完成编辑后，修改结果仍在同一详情栏显示，并通过 FR-09 的本地保存流程持久化；
- 再次打开该笔记时修改仍然存在，且未编辑的 Frontmatter、未知语法和换行约定未被无关改写。

### AC-10 iOS 只读纵切

给定一台 iOS 设备和包含 Frontmatter、Inline Tag、同名 Wiki Link、Unicode 路径的测试 Vault：

- 用户可通过文件选择器选择 Vault 文件夹，重启后自动恢复；
- App 可枚举、索引、搜索和阅读 Markdown，iPhone 紧凑导航与 iPad 三栏均可用；
- Wiki Link 跳转、收藏与标签筛选行为与 Mac 一致；
- 界面不出现任何编辑入口，整个过程不修改 Vault 中任何字节；
- 详细场景通过 [REQ-004](requirements/REQ-004-ios-read-only-client.md) 中的验收标准。

## 12. 成功指标

MVP 初期重点验证可靠性和使用闭环，而不是虚假的增长指标：

- 同步导致的静默数据丢失事件：0；
- 可恢复同步失败占已知失败的比例：100%；
- 无冲突情况下编辑到远端可见的成功率：不低于 99%，排除服务不可用；
- 本地搜索性能达到 NFR-03 的会话比例：不低于 95%；
- 核心任务“连接、找到、阅读、编辑、同步”在可用性测试中的完成率：不低于 90%；
- 崩溃率和挂起率达到 Mac Beta/发布门槛，具体目标在发布前基于基线数据设定。

## 13. 明确不在 MVP 范围

- iOS 端编辑、WebDAV 同步和上传（iOS 只读客户端按 [REQ-004](requirements/REQ-004-ios-read-only-client.md) 提前交付，不含任何写路径）；
- Obsidian 插件系统；
- Dataview、Canvas 和 Graph View；
- Block Reference 和完整 Transclusion 语义；
- 覆盖全部 Obsidian 语法和插件语法的高级富文本编辑；FR-14 只承诺 MVP 支持语法的 Bear 式原位编辑；
- App 内创建、删除和重命名文件；
- 多人实时协作；
- 跨设备收藏；
- 自建业务云后端；
- 非 WebDAV 同步协议；
- 明文 HTTP、自签名证书绕过和自定义 TLS 信任；
- AI 语义搜索、向量索引、RAG、自动标签和摘要；
- 像素级复制 Bear。

## 14. 风险与约束

| 风险 | 影响 | 产品约束 |
|---|---|---|
| WebDAV 厂商行为不一致 | 同步失败或条件写失效 | 协议能力探测、参考服务认证、条件写失败即冲突 |
| macOS 后台调度不确定 | 远端更新不及时 | 首发只依赖启动、激活、手动刷新和保存后触发 |
| Markdown 方言复杂 | 渲染或标签解析错误 | 不支持语法安全降级为原文，不重写全文 |
| 大型 Vault | 启动慢、内存高 | 增量索引、流式枚举、附件惰性缓存 |
| 路径作为身份 | 重命名导致收藏失效 | MVP 明确按删除加新增处理，不做高风险自动推断 |
| 双端并发修改 | 数据丢失 | 三方比较、条件写、保留双方 |
| 品牌相似风险 | 上架和法律风险 | 只借鉴交互原则，不复制品牌资产 |

## 15. 发布判定

满足以下条件才可称为对外 MVP：

1. AC-01 至 AC-09 全部通过；
2. 核心领域和同步逻辑行、分支覆盖率均达到 80%；
3. Critical 和 High 安全问题为 0；
4. 已完成至少一个真实 WebDAV 服务的认证测试；
5. 不存在已知静默覆盖路径；
6. 已完成隐私说明、辅助功能检查和 Mac Beta/发布验收；
7. 创建、删除、重命名等未完成能力没有通过隐藏入口提前暴露。
