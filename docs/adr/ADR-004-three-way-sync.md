# ADR-004：三方同步与无静默覆盖

- 状态：Accepted
- 日期：2026-08-01

## 上下文

仅比较本地和远端不能区分单边修改与双边修改。把“不知道”当作“未修改”会覆盖用户内容。

## 决策

- 同步规划输入为 local、remote、上次成功基线；规划器是纯函数，不执行 I/O。
- 无基线必须显式区分首次导入与账本丢失后的保守恢复；二者都不得自动上传。
- download、upload、remove-local 都携带执行前 CAS 条件；执行器发现失配必须重新规划。
- `RemoteRevision` 只表示内容身份；当前 `RemoteSnapshot` 才携带写保护条件。
- 只有从完整单值响应头解析的强 ETag 才能形成 `If-Match`。弱、缺失、列表、通配符或不可靠
  validator 一律不生成 upload。
- 412、validator 矛盾或双方修改均为冲突，绝不降级成无条件 PUT。

## 不做什么

不在 MVP 中自动合并 Markdown，不上传本地新增文件，不删除或移动远端文件。

## 后果与复审

M2/M3 必须通过真实服务验证强 ETag 与 `If-Match`。任何未通过该矩阵的服务只允许拉取，不能开启
条件上传。
