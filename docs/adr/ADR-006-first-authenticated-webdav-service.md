# ADR-006：首个认证 WebDAV 服务与能力矩阵

- 状态：Accepted（服务选择；认证能力待完成）
- 日期：2026-08-01

## 上下文

本地 fixture 已覆盖受控 PROPFIND、GET、条件 PUT 和 412，但不能证明真实 TLS、认证 challenge、
重定向或厂商行为。坚果云已被选为首个认证服务；尚无专用测试账号或应用密码，因此其能力矩阵
尚未取得认证证据。

## 决策

首个认证目标固定为坚果云 WebDAV：`https://dav.jianguoyun.com/dav/`。使用坚果云账号和为
BearObs 单独生成的第三方应用密码；不得使用账号登录密码。官方说明的免费版访问频率为每 30 分钟
不超过 600 次、单次目录请求最多 750 个条目且需分页、默认上传上限为 500 MB。500 MB 是服务硬
上限；BearObs 仍保持产品既定的单附件默认 50 MB 上限，除非另有产品决策。这些限制必须进入 M2
枚举、限流和附件策略。

- [坚果云第三方应用授权 WebDAV 开启方法](https://help.jianguoyun.com/?p=2064)
- [坚果云 WebDAV 地址与应用密码配置](https://help.jianguoyun.com/?p=5677)

本地 fixture 和 Apache `mod_dav` 可作为可重复协议对照，不是坚果云厂商认证替代品。其他服务
仅作尽力兼容，不承诺上传能力。

## 凭据与测试边界

测试只能访问专用空目录和合成 Markdown，禁止读取或写入真实 Vault。应用密码仅通过 Keychain、
受控环境变量或 CI secret store 注入，禁止进入仓库、命令历史、日志和报告。`If-Match` 的实际
服务语义尚未获得官方承诺；在陈旧 ETag 的 PUT 返回 412 且远端内容保持不变前，坚果云 profile
只能拉取，不得上传。

## 接受门槛

真实服务必须实测并留存脱敏证据：可信 TLS/主机名、401 challenge、认证成功、Depth 0/1 `207`、
超过 750 条目的分页、Unicode/空格/`%25` 路径、GET 字节和 ETag、匹配 ETag 的 PUT、陈旧 ETag
的 412 且远端内容不变，以及实际远端删除。弱/缺失 ETag、403/5xx、跨 origin 重定向等客户端安全
降级由受控 fixture 覆盖；真实服务没有提供这些情形时，只记录能力缺失，不要求人为制造故障。
