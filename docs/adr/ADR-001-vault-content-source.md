# ADR-001：Vault 内容事实源与本地工作副本

- 状态：Accepted
- 日期：2026-08-01

## 上下文

BearObs 需要离线可用，但不能把可重建索引或 UI 状态误当作笔记内容。同步故障时，混淆事实源会
直接造成笔记丢失。

## 决策

- 远端 Vault 与本地尚未同步的编辑共同构成内容事实；本地 `Files/` 工作副本承载离线内容。
- `index.sqlite`、FTS 和预览均为派生数据，删除后可重建，绝不反向生成或覆盖 Markdown。
- 同步基线与运行状态位于独立 `sync.sqlite`；冲突双方保存为冲突副本，在用户解决前不得删除。
- 本地写入必须经同目录原子替换；M0-09 的 Spike 只证明替换语义，不代替内容级 CAS。

## 不做什么

不建立业务云后端，不把收藏或阅读位置写入 Vault，也不从索引恢复用户原文。

## 后果与复审

读取路径可以重建索引；写入和冲突处理必须以工作副本、同步基线和原子写结果为准。M3 实现
`LocalVaultStore` 时复审文件协调、数据保护和内容级并发控制。
