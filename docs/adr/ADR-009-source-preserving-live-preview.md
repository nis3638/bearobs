# ADR-009：源码保留的编辑即预览（Live Preview）

- 状态：Accepted
- 日期：2026-09-28
- 替代：ADR-005 决策中“不做 Live Preview”这一项

## 上下文

ADR-005 冻结时把“不做富文本、Live Preview、自动格式化或 AST 全文回写”作为同一条决策，
因为当时要防的核心风险是把 AST 序列化回整篇文件造成的隐性内容损坏，而不是“编辑即预览”
这个呈现方式本身。REQ-002 与 REQ-003 重新确认了编辑体验目标：在右侧详情栏内原位编辑，
并获得接近阅读态的呈现。

两者并不冲突。破坏用户内容的从来不是编辑表面长得像阅读态，而是让派生渲染状态成为
第二份可保存事实源。把“不做 Live Preview”继续留在 ADR-005 里，反而与 REQ-002/REQ-003
产生字面冲突。

## 决策

- 编辑表面允许按阅读结构呈现样式（编辑即预览）；样式只是从草稿派生的临时属性投影，
  可随时丢弃重建，不得成为第二份可保存文档；
- 继续保留 ADR-005 的两条不变量：Vault 原始 Markdown 字节是唯一内容事实源；禁止把
  AST、富文本或格式化结果序列化回整篇文件；
- 保存内容只允许来自用户实际编辑对应的最小源码区间；未编辑字节保持不变；
- 不能证明安全的语法以“局部源码区域”形式原样显示和编辑，不参与样式投影；
- 首版允许安全语法标记在当前块获得焦点时显示；不承诺 Bear 的动画、品牌或像素级视觉。

## 不做什么

- 不用透明字符、零字号或不可访问附件假装隐藏语法；
- 不为投影建立持久化富文本或 HTML 缓存；
- 不顺手在编辑器内实现上传、自动保存、新建、删除或重命名。

## 后果与复审

ADR-005 中“不做 Live Preview”字样由本 ADR 替代，其余条款继续有效。REQ-002 的实现与
验收必须证明：任何样式投影都不产生保存路径，且投影构建失败时回退到整篇原始 Markdown
编辑，不丢失草稿。若后续引入无法满足最小改写不变量的渲染方案，本 ADR 须重新复审。
